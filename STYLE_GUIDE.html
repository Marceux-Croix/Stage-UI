Stage UI Style Guide

Rules, tokens and live samples for the Stage UI style. Each rule has an ID you can cite.

Version 1.02026-10-16

Stage UI is built for interfaces that center on one large canvas, the stage, such as a graph, a map or a timeline. The interface keeps attention on the stage, and it offers information density that scales to support what's displayed on the stage.

Think of a dark theater just before the show: the house lights fall, the stage glows, and everything else waits in the wings until it is called. The work is the performance, and the interface is the stagehand: quiet, precise, and always there when it is needed.

1Principles

These seven principles decide any case that the rules do not cover.

1

The stage is the product

The main content sits on a black stage. The page frames the stage and never competes with it. The stage stays black in every theme.

2

Chrome stays in the background

Controls on the stage show when the user is active and hide when the user is idle. The content is always the largest and highest-contrast thing in view.

3

One meaning per color

Violet is progress and live. Orange is broken, failed or dangerous. Yellow is "needs your input". Cyan is your selection, a match, or the primary action. Gray is everything else. No color names a category.

4

Flat surfaces, set apart by tone

Translucent fills and text weight show what is more important, not borders and shadows. Only floating layers cast a shadow.

5

Each kind of element has a fixed shape

Buttons are pills. Chips are rectangles with 8 px rounded corners. Containers are rectangles with 12 px rounded corners. Avatars and icon buttons are circles.

6

Reasons are words

A graphic shows a state. Text next to it gives the reason for the state. Do not invent an icon or a color for a reason.

7

Reduced modes are visible, and actions can be undone

When the app runs in a degraded mode (a mode with reduced function), a badge says so. An action with significant consequences asks for confirmation in place. A completed action offers Undo.

2How to use this guide

  • STYLE_GUIDE.html is the visual version of this file. It has the same rules, with live samples, both themes, and the stage drawn to the rules. It is one file with no outside dependencies. When you change one of the two files, change the other one too.
  • The words MUST, MUST NOT, SHOULD and MAY have the meanings defined in RFC 2119.
  • Each rule has an ID (for example COL-3). Use the ID in reviews and commits.
  • A blocking rule is one that stops a release when it is broken. Section 16 lists them. On the HTML page, their IDs are orange.
  • Section 17 has the complete token block, ready to paste. Section 18 is the checklist for adopting the guide.
  • Words in this guide:
    • Page: the application window and everything in it.
    • Stage: the one large canvas that holds the main content (a graph, a map, a media view, a timeline). A layout has exactly one stage.
    • Chrome: the controls that float on top of the stage.
    • Top bar: the bar across the top of the window.
    • Surface: a filled area that holds content (the page background, a panel, a menu, a card).
    • Additive fill: a see-through white layer (dark theme) or black layer (light theme) over the surface below it. It makes that surface a little lighter or darker.
    • Tonal: uses the additive fill. A tonal button is a button with an additive fill.
    • Inverted fill: a fill in the text color, so it is light in the dark theme and dark in the light theme. Text on it uses the page color.
    • Live edge: the present moment. The view is at the live edge when it shows now, and behind live when it shows a past time.
    • Media row: a thumbnail grouped with its title and metadata (CMP-ROW-6).
    • Composer: the text field where the user writes a message (section 9.12).

Reading the values

Rules keep some short forms so that the values stay compact.

  • Type. "500 14/20" means font weight 500, 14 px text and 20 px line height. Weight 400 is regular, 500 is medium and 700 is bold. A size with no weight, such as "12/18", gives only the text size and the line height. "mono" means the monospace family --mono.
  • Pixels. Values are in CSS pixels. In a native toolkit, read "px" as logical points (1 px = 1 point at scale 1.0).
  • Padding and margin. The order is top, right, bottom, left, as in CSS. "0 4 px 0 16 px" is 0 at the top, 4 px at the right, 0 at the bottom and 16 px at the left. Three values are top, then left and right, then bottom. Two values are top and bottom, then left and right: "6 px 16 px" is 6 px above and below and 16 px at each side. A grid "gap 4 px 16 px" is 4 px between rows and 16 px between columns.
  • Sizes. "64 x 36 px" is width by height. A number with "x" and no unit, such as "1.4 x", is a multiplier.
  • Window sizes. "100vw" is the window width and "100vh" is the window height. "70vh" is 70% of the window height. "min(460 px, 70vh)" means the smaller of the two values.
  • Tokens. A name such as --text-2 is a token: a named value from section 3 (colors), section 4.1 (fonts) or section 8.1 (motion). Section 17 lists all of them.
  • Opacity. "white at 50%" means white at 50% opacity. "--primary at 28%" means that token color at 28% opacity.
  • Radius is the rounding of the corners.
  • Rule IDs in parentheses, such as "(CMP-BDG-4)", point to another rule that also applies.

3Color

Only five colors carry meaning. Everything else is a neutral gray, black or white.

3.1 Semantic colors

Violet: progress and live

Progress bars, the scrubber, the live dot. Nothing else.

#8B5CF6 to #C084FC

Orange: broken, failed, danger

Failed jobs and checks, degraded services, form errors, the confirm step.

#FB923C / light #B83C0B / stage #FF7A33

Yellow: needs your input

A question, an approval, a required decision.

#FACC15 / light #A16207

Cyan: selection, match, primary

On the stage, only the selection or a match.

#22D3EE / light #0E7490

Gray: everything else

Including "working" and every kind of waiting. Add a word for the reason.

#9AA0B4 / light #5A6072
COL-1Violet (--accent, --progress) MUST mean only progress or live. It appears on progress bars, the timeline scrubber and the live dot. Its one other use is the single accent element of the brand mark (AST-2).
COL-2The count badge on a notification button and the live status badge use --indicator, a deeper violet, because white text on --accent has a contrast below 4.5:1. These two badges are the only other uses of violet.
COL-3Yellow (--needs-input) MUST mean "needs your input": a question, an approval, a decision, or a failure that the user must deal with. It means nothing else, on the stage or on the page. An indicator that sums up several items shows a failure as yellow (CMP-BDG-3).
COL-4Cyan (--primary) MUST mean one of these: the current selection, a search or filter match, the primary action, or "new since you last looked". On the stage, cyan means only the selection or a match.
COL-5Gray (--text-2, and #9AA0B4 on the stage) is the default for all other states, including "working" and every kind of waiting (queued, blocked, held by a limit, in conflict). A waiting state names its reason in words.
COL-6Green (--green) MAY show a healthy or passed state, in text or in an 8 px status dot. Do not use green on the stage.
COL-7Orange (--danger, --danger-bg and, on the stage, --stage-danger) MUST mean broken, failed or dangerous. It marks the failed or broken thing itself: a failed job, check or step, an actor that stopped with an error, a degraded service, a form error, and the confirm step before an action with significant consequences. An indicator that sums up several items never shows orange; it shows a failure as yellow. Orange means nothing else.
COL-8Color MUST NOT identify a category, such as a vendor, a team or a type of user. Use a letter, a label or an icon instead.
COL-9A color MUST NOT be the only way a meaning is shown. Pair it with text, a tooltip or an accessible name (the name that a screen reader announces).

TYP-1Use weight 500 for names, labels and buttons. Use 700 only for page and dialog titles, the wordmark, and the part of a search suggestion that completes what the user typed (CMP-SRCH-3).

TYP-5Use sentence case for all labels, titles, badges and buttons: capitalize only the first word and proper names. Do not set words in all capitals.
TYP-6Inline code uses --mono on an --additive fill, with radius 4 px and padding 1 px 4 px. Inside cards, inline code does not wrap.
TYP-7Turn on font smoothing (-webkit-font-smoothing: antialiased).

5Spacing, shape and elevation

Spacing comes in steps of 4 px. Bigger things get rounder corners. Only things that float over the page cast a shadow.

5.1 Spacing

Preferred steps

A value that a component rule states (for example 3, 5, 10, 14 or 36 px) wins over the steps.

SPC-1Page gutters (the space along the window edges) are 16 px in the top bar and 24 px in the content columns.
SPC-2The gap between the primary column and the secondary column is 24 px. The gap between stacked panels is 12 px.
SPC-3Rows inside panels have 16 px of padding at the left and right. Dense rows have 4 to 6 px of padding at the top and bottom.
SPC-4The gap between an icon and its label is 6 px in buttons and chips, 12 px in rows with a tile, 16 px in menu items and 24 px in expanded navigation entries.
SPC-5Chips in a filter bar are 12 px apart. Chips and small buttons inside a card are 8 px apart.

LAY-7Below the stage, from top to bottom: the title row (40 px avatar, 700 18/26 title, 12/18 metadata), then the pending action cards, then the composer.

LAY-9When the content above or below the stage changes height, fit the stage to its new space in the next frame.

7Iconography

Icons come from Material Symbols Outlined, weight 400. They are outlined at rest and filled when active.

Rest and active (ICO-3)

Sizes (ICO-1)

The icon set in use. Hover to highlight.

ICO-1Use Material Symbols Outlined, weight 400. The default size is 24 px, and this includes the check column in menus. Use 20 px in small icon buttons and dialog tabs, 18 px in small buttons and badges, and 16 px next to 12 px text.
ICO-2Icons take the current text color (currentColor). Draw them as a mask or a tinted glyph, not as colored images.
ICO-3Use the outlined form at rest. Use the filled form for the active state: the current navigation entry, the trigger of an open menu, a toggle that is on.
ICO-4In a button with a label, a leading icon moves 6 px to the left, into the left padding (4 px in size S).
ICO-5An empty-state icon is 64 px with no container, or 36 px inside a 72 px --additive ring.
ICO-6Icons on the stage are white. Status icons inside stage cards are 13 to 18 px.

MOT-1Things enter more slowly than they leave. An element that appears takes 150 to 350 ms. An element that leaves takes 100 to 200 ms.
MOT-2When the user asks for reduced motion (prefers-reduced-motion: reduce), all transitions and animations MUST have zero duration, blinking stops (the dot stays solid), and scrolling is instant.
MOT-3"Working" shows as a blink. The opacity goes from 1 to 0.3 and back over 1.6 s, with ease-in-out, and repeats without end. On the stage canvas, the lowest opacity is 0.35. The blink applies to gray working dots and to the gray aggregate indicator (CMP-BDG-4).
MOT-4The attention wiggle is only for "needs your input" on a collapsed control. Each cycle is 4.6 s: a 600 ms spring, then rest. During the spring, the control rotates +8, -6, +4 and -1 deg in turn, and scales up to 1.08. The wiggle stops on hover. A new needs-input item starts it again.
MOT-5A live event on the stage shows as one gray ring. The ring grows from 5 to 35 px and fades out over 1.2 s. It has no color.
MOT-6Do not move layout that the user is pointing at. Keep the list order stable when an item resolves (see CMP-CARD-4).

Sizes 48, 40, 36 and 24 px. The letter says what kind of actor it is. Color never does. The dot shows the actor's state: blinking gray means working, yellow means it needs you, orange means it stopped with an error, and no dot means idle.

    THM-2Switch themes with one attribute on the root element (data-theme="dark" or "light"). Set color-scheme to match.
    THM-3The stage, its overlays and its tooltips do not change with the theme.
    THM-4Components take theme colors only from tokens. A fixed color is allowed only where this guide states it: sections 3.3 and 3.4, and the literal color values in component and stage rules. Any other color literal in the code is a defect.

    14Accessibility

    A11Y-1All text meets WCAG 2.2 AA contrast on its surface in both themes: 4.5:1, or 3:1 for large text. Non-text parts that carry meaning meet 3:1. Disabled text and decorative borders are exempt. Section 14.1 lists the measured pairs. Measure any new pair of tokens before you use it.
    A11Y-2Every control has an accessible name. Controls that show only an icon use aria-label.
    A11Y-3Use native roles, or the matching ARIA pattern: combobox and listbox for search, menu and menuitemcheckbox for menus, tablist for dialog sections, radiogroup for feed switches and single-choice lists, switch for toggles, slider for the timeline, and dialog with aria-modal for modals.
    A11Y-4Live feeds are polite live regions (announced without interrupting). Form errors are assertive (announced at once). The snackbar host is a polite status region.
    A11Y-5The stage canvas can take focus. Its accessible name lists its keys. The legend is its description.
    A11Y-6A state shown only by color (dots, rings) also appears in the accessible name or the tooltip.
